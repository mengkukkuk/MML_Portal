Table reference

Tablevision_data.production_hourly_log
Grainone row per camera per hour
Key columnslocation, code, period_start, batch_id, count_total, defect_total
FeedsKPI Strip, Throughput Timeline, Quality Exceptions, Camera Summary (counts)

Tablevision_data.camera_defect_logs
Grainone row per camera per batch (historian of camera_defect)
Key columnslocation, code, name, batch_id, defect_array, created_at
FeedsDefect Pareto, Camera Summary (last_seen/worst_defect), Defect Batch Log

Tablevision_data.cameras
Grainone row per camera (registry)
Key columnslocation, code, name, defect_labels
FeedsLine/Camera filter pickers, camera display names, defect-type labels for the pareto

A camera's identity throughout is (datasource_id, location, code), not just (location, code) — see reports.py's module docstring. All three tables above live under the vision_data schema of whichever datasource(s) the logged-in user has selected; the schema name itself is per-datasource-configurable (localbase.datasources.db_schema), it just happens to be vision_data for every camera datasource currently configured.
